# 国王模拟战斗预览

2026-10-25。独立 Godot 4.5.1 窗口，已按用户要求撤掉披风双栏对照，改为单场景训练场。此轮只调整预览中的动作与声音时序，已安装 Mod 的 DLL、PCK 及游戏等待逻辑保持原样。

## 打开

```powershell
powershell -ExecutionPolicy Bypass -File D:\King_Workspace\05_Preview\start-preview.ps1
```

**直接双击项目根目录的 `启动战斗预览.cmd` 即可，无需输入命令。** 启动失败会保留报错窗口；可把错误文字发回。入口按自身所在目录定位工程，从其他工作目录启动也有效。

首次准备或更新本地素材：加 `-Prepare`。脚本调用 `prepare_battle_preview.py`，从本地《死亡细胞》数据和现有 Mod PCK 生成 `Generated/`，不部署 Mod。需要本地原始资源与 Pillow。已有 Generated 素材时直接启动，不会重新抽取。

## 操作

- 选择蓝王/白王及具体武器；当前默认平底锅，包含武士刀、重剑等 7 组标准武器、24 段，均有原版音频。权杖、刺剑自定义 C 段、墓碑的工程拼接段暂不放进原作节奏试验，避免把推测当作完整还原。
- **打击 · 单次**：模拟一次快速模式攻击，可连续手动点击。当前挥击保留到命中、刀光触发后，再留约 0.06 秒接下一段；后续攻击最多保留一组待接动作，额外输入合并进该组。
- **原作连段**：按原始蓄力及攻击后控制锁安排下一段，可连续观察完整一套。
- **星尘 · X**：星尘（Stardust）X 星星随机攻击 X 次，默认 20；**极限 · 星尘 50 连击**直接发起 50 次。基础输入间隔 0.175 秒，伤害在每次输入后 0.075 秒结算，随后 0.1 秒等待。该节拍来自游戏快速模式的基础调用链，不包含能力/遗物额外演出及帧调度耗时。
- **循环演示**：演示结束后等待 0.8 秒重放；每轮重置靶标和计数，避免上轮死亡影响下一轮。
- 默认启用声音；暂停停止当前发声。可用 0.25× / 0.5× 放慢观察，音频保持原音高。
- 上/下一帧用于暂停观察当前动作，不重放游戏伤害。空格暂停，方向键观察帧。受击、胜利、死亡可直接查看，死亡隐藏披风。
- 状态栏记录结算/输入、挥中次数、合并次数、下一组承接的攻击次数，以及最长动作滞后。三个训练假人的受击闪光、血条、数字是模拟反馈，不是新加入 Mod 的敌人特效。

## 原作节奏来源

本轮进一步核对了本地原游戏字节码，关键证据在 `artifacts/scarf-research/original-disasm/`：

- `Boot.init`：引擎 wantedFPS=60。
- `Entity.initSprite` 的 onAnimManAlloc 回调（6843）：角色 AnimManager.genSpeed=0.5，基础图集帧率 30；`Weapon.dynOnAttackAnim` 再乘各段 animSpd 和施放速度，当前使用无增益的基础速度。
- `OldSkill.useWeaponSkillInfos` / `update`：原表 hitFrame 转换为 2 倍逻辑帧，剩余蓄力进入该区间才启动身体攻击动画，故预览保留 `max(0, charge-hitFrame/30)` 的预备时间。之前直接从动作第 0 帧一起播放并不能还原这个时序。
- `OldSkill.update`：fxStartFrame 决定独立 FX 触发门限；`Weapon.dynOnFxFrame` 同时触发挥击音和刀光。
- `Fx.playWeaponAnimFromObject`：刀光实例速度为 0.5 × animSpd × castSpeed，普通 FX 基础 30 图集帧/秒。
- 原始 data.cdb 的 charge、hitFrame、lockCtrlAfter、animSpd、fxProps 及声音映射直接生成到 `Generated/battle_data.json`，不覆盖运行时武器定义。

吸血鬼杀手时序修正（2026-10-25）：原版三段 FX 在第 0 帧创建，但分别有 6、10、17 帧全透明前导；工程导入时已删掉这些帧。预览之前将导入首帧误当原版第 0 帧，导致鞭光提前约 0.200、0.333、0.567 秒。生成器现在从工程文件名取得截去的帧数，并核对原版图集对应帧全部透明，再恢复这段视觉等待；挥击声仍保留原作释放时点。验证检查三段刀光首帧分别对应身体第 6、10、17 帧，暂停逐帧查看也遵循同一门限。此修正仅作用于当前预览，不修改旧版游戏播放方式。

巨镰映射修正（2026-10-25）：原表 `TickScytheRight`、`TickScytheLeft` 各有两段，工程将其组合为 A1/A2/B1/B2 四段。左手两段原表明确采用交叉命名：`atkScytheB1 → fxAtkScytheB2`、`atkScytheB2 → fxAtkScytheB1`，不是身体倒放或互换。共享 weapons.json 已修正这两处，预览读取同一映射；原始图集重建后，与工程已导入的 B1/B2 全部 12 张刀光图片逐像素核对一致。原生验证检查四段实际选用的刀光及正向播放。尚未覆盖游戏安装包。

生成器新增 `Generated/weapon_source_audit.json`，列出来源武器、原表段序号、身体、原始 FX、工程 FX、播放速度及已核实的裁帧等待。当前 24 段中有 19 段直接符合原表 FX，另有武士刀末段及平底锅四段使用现有工程变体，明确标为待专项复核，不将它们宣称为已完整还原。以后新的非原表配对会使准备脚本报错；多个原表段共用同一身体时也不再静默取第一条，而是排除并等待专门处理。

击中声改为跟随每次实际伤害结算，音色取该次攻击所属挥击的武器段；挥击声、刀光仍跟随可见动作，避免快速出牌时始终等不到命中声。极限输入会出现多次伤害/撞击声对应一次挥击，这是保留原作挥击速度的取舍，尚未移植到实机。原版攻击造成的位移、命中停顿、增益动态施法速度及特殊武器独立逻辑未完整模拟，因此称为原作基础节奏试验，不声称整个死亡细胞运行时已移植。

披风继续复用 Mod 中同一份 ScarfRig.gd，包含已验收的头部挂点、配色、原版重力、风、出招推力和前后遮挡。

## 压力测试的含义

上一轮直接重启动作会使 50 连击的前 49 段在挥中前被覆盖。本轮取消这个策略：保护当前挥击，最多留一组后继动作，后继尚未启动时的新输入并入该组；每次挥击按可见顺序推进武器连段，不因合并跳过动作段数。当前动作完成命中和刀光事件后，可省去剩余收招接下一段；输入停下后正常播放最后一段收招。

这样不会积累几十段排队动画，也不改变伤害结算节拍或全局加速动作。代价是伤害次数与挥击次数在极限情况下不再一一对应；重武器仍有原作前摇，允许动作晚于伤害。当前 50 连击测试：平底锅 27 次完整挥中、最长滞后约 575ms；重剑 17 次、约 1025ms；巨镰 13 次、约 1275ms。七组武器的 50 次伤害均各触发一次击中声，没有命中前打断。滞后按该挥击所承接的最早输入后 0.075 秒到动作命中计算，并非游戏伤害被推迟。
