# 原版围巾逻辑核对与初版纠正

2026-10-24。用户指出初版光带像尾巴/翅膀，待机时的方向、根节点及重力不对。

## 初版的错误

初版只拿到了原贴图和皮肤配置，没有核对参数在原程序中的用法：

- 选择 `Bip001 Spine2` 作为根挂点；实际默认使用 `headBone`。
- 自拟持续向后的水平力，并将重力乘以 `0.018`，导致静止状态也向后伸展。
- 将 `count` 当作点数，实际为分段数量，应有 `count + 1` 个位置点。
- 使用自拟的绳索约束、粗细衰减与高亮倍率，未遵循原分段贴图的缩放与透明度公式。

资源引用完整、数值不发散，只能证明程序能运行，不能证明挂点含义或视觉正确。该初版不应当作为原作效果的还原依据。

## 证据来源

从用户本机 `D:\Dead Cells\deadcells.exe` 中读取内嵌 HashLink 字节码，定向解析原版围巾类型；没有运行或修改游戏程序。

解析工具为开源 [crashlink](https://github.com/N3rdL0rd/crashlink)，本地检出位于 `artifacts/scarf-research/crashlink/`。反汇编在 `artifacts/scarf-research/original-disasm/`，辅助伪代码在 `original-pseudo/`。伪代码可能不完美，结论以对应指令与本地配置交叉核对。

关键方法与原始调试行号：

- `en.Hero.get_headX/Y`（f@1983/1984，`en/Hero.hx:1191-1210`）：读取 `headBone` 逐帧坐标并结合精灵原尺寸和 pivot。
- `tool.Scarf` 构造（f@4877，`tool/ScarfSegment.hx:123-142`）：国王配置 `props={}`，因此 `isCape`、`lockBehind` 都不启用；创建 `count` 个分段，深度为 `i/(count-1)`。这里的 `isCape` 是程序分支名，不是用户对视觉外观的称呼。
- `tool.ScarfSegment` 构造（f@4876，原始行 235-262）：默认额外贴图长度 3，粗细相位 0，深度缩放系数 0.7，贴图 pivot 为 `(0.1,0.5)`。
- `tool.ScarfSegment.postUpdate`（f@4874，原始行 338-489）：根位置、重力、阻尼、长度变化、分段旋转与贴图缩放。
- `en.Hero.fixedUpdate`（f@2153，原始行 4973-4978）：关卡风是单独输入；非锁定分支以 `0.16*(0.6+0.4*cos(ftime*0.015))*wind` 调用 `pushScarf`，关卡未指定 wind 时默认 1。因此原版存在环境风，但它不等于“永远朝人物背后”的人为力。
- `Assets.checkBackFrames`（f@5856）及 `data.cdb/backFrames`：动作前后朝向窗口决定围巾前/后层，独立于挂点轨迹的第三个整数。

## 本轮预览已纠正

- 全部 53 个动作、1443 帧改接 `headBone`。
- 默认根位置按原公式取头部位置，并加背侧 `-3` 像素、纵向 `+1` 像素及该条光带的 attach 偏移。外层父节点负责整体朝向翻转。
- 采用原版非 linked、非 isCape 分支的速度更新、重力和长度限制。静止、无风时没有人为水平力。
- 阻尼使用原 friction；长度随原 runFactor 插值并平滑收敛；分段纹理的宽度、厚度、pivot 和首段透明度按原公式。
- 去掉初版的常驻风力/飘动滑条。新增“仅看光带”，可查看被身体遮挡的挂点及下垂形状。

专项检查通过：固定头部、静止且无风时，五条链均向下垂落，尾端无水平漂移；根节点偏移、分段数正确。原有资源检查与逐帧/刀光回放检查仍通过。

## 进一步复刻：风、出招推力与前后层

本轮根据用户继续复刻的要求补齐：

- `Assets.initBackFramesCache`（f@5855）：`endFrame=0` 转成 999，帧范围包含两端。按原图帧路径导出模式 0 的前后层状态，当前动作资源中共 141 帧切至前层；进入前层时原背侧 `-3` 偏移也随之取消。
- `HeroWeaponsManager.onWeaponUse`（f@4846）：调用 `hero.pushScarf(-hero.dir)`。预览在 31 个现有攻击动作起点触发一次，不改变身体或刀光的既有时序。
- `ScarfSegment.push`（f@4871）：每段施加 `[8,10)` 的随机水平速度增量，按 `0.3+0.7*(1-depth)` 衰减，并设置 0.4 秒活跃期；活跃时 runFactor 的目标至少为 0.6，再应用原有调制和平滑。
- 关卡风按原 `0.16*(0.6+0.4*cos(ftime*0.015))*wind` 进入同一推力通路，独立于角色朝向；窗口提供 0、1、-1、-2 的对照。原数据中未指定时默认 1，PrisonCourtyard 为 -2，PrisonRoof 为 3，Throne 为 -3；窗口默认 0 是为了延续无风检查环境，不声称它就是所有原版关卡的默认环境。
- 光带转身时将自由端和速度转换到新朝向坐标，保持原来的世界位置；不再将整条已形成的光带直接镜像到另一侧。
- 贴图变体由每段初始化随机选择，预览固定随机种子以便比较；不再固定交替。预览随机序列不声称与原游戏相同。
- 动作和光带共用时间步进；逐帧回退和拖动进度恢复动作起点的链、速度、相位与 RNG 状态，再重新演算，避免保留未来状态。

新增验证通过：平底锅第 7/8/18/19 帧前后层边界及绘制顺序；回退再前进的光带一致性；正反风与转身后世界风向保持；武器反向推力和活跃期消退。四种场景已通过原生渲染检查并保存画面。

时基核对：`libs.Process._update` 使用 `p.tmod=tmod`、`p.ftime+=tmod` 更新，`getDefaultFrameRate` 返回 Heaps 的 `hxd.Timer.wantedFPS`。预览继续以 60 Hz 的归一化步进运行；没有宣称完整复制 Heaps 的所有运行时调度。

## 尚未作为完整原作运行环境接入的部分

当前窗口没有模拟完整原游戏的角色世界位移、碰撞及风场空间变化，也没有原游戏的完整渲染后处理。原游戏随机流与 Heaps 调度仍与此独立预览不同。因此当前是原逻辑移植预览，不能称为原游戏逐帧复刻。
